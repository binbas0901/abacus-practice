# Juni's lesson voice — source of record

This folder is how Juni's spoken lessons are **protected and repurposed**. The
app ships the finished pack at `audio/juni-lines-lesson.js`; this folder is what
regenerates it.

## What's here
- `lesson-manifest.json` — the 223 lesson lines: `[{id, text}, ...]`. The `text`
  is the exact wording Juni speaks; `id` names its clip file.
- `lines.tsv` — the same lines as `<id>\t<text>`, the input `gen.sh` reads.
- `gen.sh` — records each line with ElevenLabs into `clips/<id>.mp3`. Resumable:
  it skips any line that already has a clip, so re-running only records what's new.
- `build_pack.py` — stitches the clips into `audio/juni-lines-lesson.js`.
- `clips/` — the raw per-line mp3s (not committed; regenerated by `gen.sh`).

## Why keyed by text (the repurposable part)
The pack maps **line text → audio**, not id → audio. So if a lesson script is
reworded, only that one line needs re-recording; every unchanged line keeps
playing from the pack. The lesson code looks a clip up with
`Classroom.Voice.find('juni', <line text>)`, and the demo narrator
(`narrateStep` / `playSteps` in `app.js`) times the bead moves to the clip so
voice and beads stay in sync.

## Regenerate / extend
1. Edit the demo scripts in `curriculum.js` (the `explain` / `explainMul` `say`
   templates), then re-derive `lesson-manifest.json` / `lines.tsv` with every
   line the lessons can produce.
2. `ELEVEN_KEY=sk_xxx bash lessonvoice/gen.sh`  (records only missing lines)
3. `python3 lessonvoice/build_pack.py`  (rebuilds `audio/juni-lines-lesson.js`)
4. Bump the version, run `bash tests/run.sh`, commit.

The ElevenLabs key is never stored in the repo — pass it via `ELEVEN_KEY` for the
one run that records, then discard it.
